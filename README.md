## 三、怎么用这份教程（重要，别跳过）

### 每个知识点的学习循环

```
读讲解  →  敲代码  →  故意改错看报错  →  说出"一句话记住它"
 5 min     5 min        3 min                1 min
```

**"故意改错看报错"是整份教程里最值钱的动作。**
大多数人对 TS 的恐惧来自"看到红线就慌"。
你把错误故意制造出来 20 次之后，红线就变成了朋友——它是在你提交代码之前替你挨骂。

教程里每一处报错都是**从真实编译器上抄下来的**，不是编的。
所以你也可以自己复现：把代码改坏，看看是不是同一句报错。

### 三条铁律

1. **不要背 API。** TS 的类型系统只有十来个核心概念，其余全是组合出来的。背组合是背不完的。
2. **不要一开始就开最严的 strict。** 先用宽松配置跑通，再一步步收紧（第 08 章带你走一遍）。
3. **看不懂的复杂类型，先当成黑盒用。** 比如 `Partial<Pick<User, 'name'>>`，先会用，学完第 06 章回来看，会发现它简单得很。

## 四、把环境跑起来

你只需要 **Node.js**。要用 `node xxx.ts` **免参数**直接运行，需要 **v23.6+ 或 v22.18+**（本教程基于 v24）。

```bash
cd examples
npm install          # 或 pnpm install，配套工程用的是 pnpm
```

然后随便挑一个示例文件验证：

```bash
node 01-心智模型.ts
```

能看到输出，就说明**你的 Node 版本够新，可以直接运行 TypeScript 文件**，
不需要装 `ts-node`、`tsx` 这些老工具。

再做一次**类型检查**（注意：这跟"运行"是两件不同的事，第 08 章专门讲）：

```bash
npx tsc --noEmit
```

没有任何输出 = 类型全对。

> `examples/` 里已经装好了 `typescript@5.9.3` 和 `@types/node`，并配好了一份 `tsconfig.json`。
> 你可以直接拿来用。

### 一个真实的坑（值得提前知道）

Node 的原生类型擦除**只支持"可擦除语法"**。下面这些会报错：

```bash
$ node test.ts
SyntaxError [ERR_UNSUPPORTED_TYPESCRIPT_SYNTAX]:
  TypeScript enum is not supported in strip-only mode
```

**不可擦除的四种语法**（它们都需要生成新的运行时代码）：

| 语法 | 例子 |
|---|---|
| `enum` 声明 | `enum Color { Red }` |
| 含运行时代码的 `namespace` | `namespace A { export let x = 1 }` |
| 构造函数参数属性 | `constructor(private name: string) {}` |
| import 别名 | `import { foo as bar } from ...` 的某些形式 |

另外**装饰器（decorator）也不支持**，会直接报解析错误。

**推荐做法**：不用 `enum`，用 `as const` 对象替代（第 06 章讲）。
在 `tsconfig.json` 里打开 **`erasableSyntaxOnly: true`**，
`tsc` 就会在你写出不可擦除语法时**当场报错**，而不是等你运行时才发现：

```jsonc
{
  "compilerOptions": {
    "erasableSyntaxOnly": true   // TS 5.8+：禁止一切不可擦除语法
  }
}
```

配套工程**已经开了这个开关**，所以你可以放心：`examples/` 里每个文件都能被 `node` 直接运行。
效果是这样的：

```ts
enum Bad { A, B }
```

```text
error TS1294: This syntax is not allowed when 'erasableSyntaxOnly' is enabled.
```

> 补充三点：
> - `--experimental-transform-types` 能让 Node 跑 `enum`，但它在 **Node v26 已被移除**。
>   所以「用 `as const` 替代 `enum`」不只是风格偏好，是**面向未来的选择**。
> - Node **不读 `tsconfig.json`**，所以 `paths` 别名在 `node x.ts` 直跑时**不生效**（第 08 章讲怎么绕）。
> - 源码里相对导入必须带扩展名：`import './file.ts'` ✅，`import './file'` ❌。
>   这就是配套 `tsconfig.json` 里开 `allowImportingTsExtensions` 的原因。

## 六、先看三段代码，找找感觉

别怕看不懂，先感受一下 TS 和 JS 的差别。

**第一段：类型是"写在旁边的说明书"**

```ts
function add(a: number, b: number): number {
  return a + b;
}

add(1, 2);      // 通过
add('1', 2);    // 编译期就报错，代码根本跑不起来
```

**第二段：类型能推导，所以大部分时候你不用写**

```ts
const user = { name: 'Tom', age: 18 };

user.name.toUpperCase();   // OK

user.age.toUpperCase();
// 报错：Property 'toUpperCase' does not exist on type 'number'. (TS2339)
```

**第三段：判别联合能删掉一整类运行时 bug**

```ts
type State =
  | { status: 'loading' }
  | { status: 'success'; data: string[] }
  | { status: 'error'; error: string };

function render(s: State): string {
  switch (s.status) {
    case 'loading': return '加载中';
    case 'success': return s.data.join(',');   // ← data 直接可用，不需要 ?. 也不需要 !
    case 'error':   return s.error;            // ← error 直接可用
    default:        return assertNever(s);     // ← 漏了分支立刻编译报错
  }
}
```

看出来了吗？
**TS 不是给 JS 加了一堆限制，而是让你在写代码的时候，脑子里少记一些东西。**
你不再需要记住"这个字段在什么状态下才存在"，编译器替你记着。

这就是它的全部价值。剩下的都是细节。

## 七、承诺与免责

**这份教程保证：**

- 每个知识点都有可运行的代码，全部通过 `tsc --noEmit --strict`。
- 每处报错信息都是从真实编译器上抄下来的，包含错误码，你可以自己复现。
- 讲"为什么这么设计"，不只是"怎么写"。第 00 章引用了 TypeScript 官方的设计目标原文。

**这份教程不保证：**

- 让你成为类型体操大师（那需要几个月，而且工作中基本用不到）。
- 覆盖所有边角 API（那需要查手册，而查手册是正常的工作方式）。
