## 5.1 泛型是什么：类型版的"函数参数"

### 从一个真实需求开始

你要写一个"原样返回"的函数：

```ts
function identity(value: string): string {
  return value;
}
```

现在你还想要一个能收数字的。于是复制一份：

```ts
function identityNumber(value: number): number {
  return value;
}
```

再来个布尔的？

```ts
function identityBoolean(value: boolean): boolean {
  return value;
}
```

你很快会发现：**要写无限个。**

那用 `any` 呢？

```ts
function identity(value: any): any {
  return value;
}
```

**这就把类型信息彻底丢了：**

```ts
const n = identity(42);
//    ^? any   ← 我要的是 number 啊！
n.toUpperCase();   // 编译通过，运行时炸
```

### 泛型登场

```ts
function identity<T>(value: T): T {
  return value;
}

const n = identity(42);
//    ^? 42   ← 类型被原样保留了！
const s = identity('hi');
//    ^? "hi"
```

### 逐字拆解 `<T>`

```ts
function identity<T>(value: T): T {
  //              ↑        ↑  ↑
  //              │        │  └─ 返回值是 T
  //              │        └──── 参数是 T
  //              └───────────── 声明一个"类型参数"，名字叫 T
}
```

**读作：**

> "这个函数有一个**类型参数** `T`。你调用它的时候，把你想用的类型填进 `T`。
> 参数 `value` 的类型是 `T`，返回值的类型也是 `T`。"

### 类比：函数参数 vs 类型参数

你已经很熟悉**值参数**了：

```ts
function double(x) { return x * 2; }
//              ↑ 这里 x 是个"占位符"，调用时才填具体的值
double(5);      // x 填 5
double(10);     // x 填 10
```

**泛型就是同一个思路，只是把"值"换成了"类型"：**

```ts
function identity<T>(value: T) { return value; }
//                ↑ T 是个"类型占位符"，调用时才填具体的类型
identity<number>(5);    // T 填 number
identity<string>('a');  // T 填 string
```

所以一句话：

> **泛型 = 类型层面的函数参数。**

（`<T>` 里的 `T` 只是"Type"的首字母，是个约定俗成的名字，你叫它 `<X>` 也完全可以。）

### 那 `any` 和泛型的本质区别是什么？★

这是本章最重要的一句话，请读三遍：

> **泛型的作用不是"能接受任何类型"，而是"能建立类型之间的关系"。**

`any` 是**没有关系**的：

```ts
function bad(x: any): any {
  return x;
}
// 输入和输出之间没有任何约束。你给它一个 string，它可能还你一个 number，编译器不管。
```

泛型是**有关系**的：

```ts
function good<T>(x: T): T {
  return x;
}
// 输出必须和输入"是同一个 T"。
// 你给它 string，它只能还你 string。编译器死盯着这一点。
```

**看一个能证明"这关系真的存在"的例子：**

```ts
function pair<T>(first: T, second: T): [T, T] {
  return [first, second];
}

pair(1, 2);        // ✅ 都是 number
pair('a', 'b');    // ✅ 都是 string
pair(1, 'b');      // ❌ 报错：两个参数必须"同一种" T
```

```text
error TS2345: Argument of type 'string' is not assignable to parameter of type 'number'.
```

**用 `any` 永远写不出这种约束。**

> **一句话记住它：泛型不是"万能类型"，它是"类型之间的关系声明"。**

## 5.2 泛型能用在三个地方

### 地方 1：函数（最常用）

```ts
function first<T>(arr: T[]): T | undefined {
  return arr[0];
}

const a = first([1, 2, 3]);
//    ^? number | undefined
const b = first(['x', 'y']);
//    ^? string | undefined
```

箭头函数的写法：

```ts
const first2 = <T>(arr: T[]): T | undefined => arr[0];
```

> **注意 `.tsx` 文件里的坑**：在 React 的 `.tsx` 文件里，`<T>` 会被当成 JSX 标签。
> 解决办法是加个逗号：`const first2 = <T,>(arr: T[]) => arr[0];`
> 或者用 `function` 声明。

### 地方 2：接口 / 类型别名

```ts
interface Box<T> {
  value: T;
}

// 或者
type Box2<T> = { value: T };

const numBox: Box<number> = { value: 42 };
const strBox: Box<string> = { value: 'hi' };
```

```ts
const wrong: Box<number> = { value: 'x' };
```

```text
error TS2322: Type 'string' is not assignable to type 'number'.
```

**实战里最常见的泛型接口**：

```ts
interface ApiResponse<T> {
  code: number;
  message: string;
  data: T;
}

type UserResponse = ApiResponse<{ id: number; name: string }>;
type ListResponse = ApiResponse<string[]>;

// 带默认值（后面讲）
interface Paged<T = unknown> {
  items: T[];
  total: number;
  page: number;
}
```

**为什么这个模式这么重要？**
因为它把"响应外壳"和"业务数据"解耦了。
外壳（code / message）只用写一次，业务数据用 `T` 插进去。

### 地方 3：类

```ts
class Stack<T> {
  private items: T[] = [];

  push(item: T): void {
    this.items.push(item);
  }

  pop(): T | undefined {
    return this.items.pop();
  }

  get size(): number {
    return this.items.length;
  }
}

const s = new Stack<number>();
s.push(1);
s.push(2);
// s.push('a');   // ❌ TS2345
console.log(s.pop(), s.size);
```

**泛型类的一个实用场景：类型安全的仓库（Repository）**

```ts
class Repository<T extends { id: string }> {
  private store = new Map<string, T>();

  save(entity: T): void {
    this.store.set(entity.id, entity);
  }

  findById(id: string): T | undefined {
    return this.store.get(id);
  }

  all(): T[] {
    return [...this.store.values()];
  }
}

interface Product {
  id: string;
  name: string;
  price: number;
}

const products = new Repository<Product>();
products.save({ id: 'p1', name: '键盘', price: 299 });
console.log(products.findById('p1')?.name);
```

> **一句话记住它：泛型可以用在函数、接口/类型别名、类三个地方；接口是实战中最常见的一个。**

## 5.3 类型参数是"给编译器看的变量"

### 名字随便起，但有惯例

```ts
function f<T>(x: T): T { return x; }
function g<X>(x: X): X { return x; }   // 完全一样
```

社区惯例（先照抄，熟练了再改）：

| 名字 | 传统含义 | 例子 |
|---|---|---|
| `T` | Type，第一个类型参数 | `identity<T>` |
| `U` / `V` | 第二、第三个 | `map<T, U>` |
| `K` | Key | `Record<K, V>` |
| `V` | Value | `Map<K, V>` |
| `E` | Element / Error | `Array<E>` |
| `R` | Result / Return | `(x: T) => R` |
| `P` | Props（React） | `Component<P>` |
| `S` / `A` | State / Action | `Reducer<S, A>` |

**但如果一个类型参数有明确的业务含义，就用业务名：**

```ts
// ❌ 读起来费劲
function merge<T, U>(a: T, b: U): T & U { /* ... */ }

// ✅ 一眼明白
function merge<TUser, TOrder>(a: TUser, b: TOrder): TUser & TOrder { /* ... */ }
```

**现代 TS 社区更流行的风格是直接加 `T` 前缀做业务名**：
`TData`、`TState`、`TProps`、`TResult`。这样在代码里一眼能看出"这是个类型参数，不是具体类型"。

### 类型参数只在"编译期"存在

第 00 章的哲学二在这里又出现了：

```ts
function identity<T>(value: T): T {
  console.log(typeof T);   // ❌ 做不到
  return value;
}
```

```text
error TS2693: 'T' only refers to a type, but is being used as a value here.
```

`T` 在运行时是**不存在的**。这解释了：

```ts
function create<T>(): T {
  return new T();          // ❌ TS2693
}
```

**正确做法：把构造函数当参数传进来。**

```ts
function create<T>(Ctor: new () => T): T {
  return new Ctor();
}

class Cat {
  meow() { return '喵'; }
}
const cat = create(Cat);    // cat 是 Cat
console.log(cat.meow());
```

> **一句话记住它：`<T>` 里的 T 是给编译器看的变量，运行时它不存在——所以不能 `new T()`、不能 `typeof T`。**

## 5.4 泛型约束 `extends`：给 T 划个范围

### 问题：无约束的 `T` 什么都不能做

```ts
function getName<T>(obj: T) {
  return obj.name;
}
```

```text
error TS2339: Property 'name' does not exist on type 'T'.
```

**为什么？** 因为 `T` 可以是**任何东西**——包括 `number`、`null`、`undefined`。
万一调用者写 `getName(42)` 呢？`42.name` 是什么？

编译器说："**你说 T 是任何类型，那我就只能按'任何类型'来对待它，那我什么属性都不敢让你访问。**"

这其实是**哲学三（结构化类型）的必然结果**：要访问一个属性，你必须证明这个形状存在。

### 用 `extends` 证明

```ts
function getName<T extends { name: string }>(obj: T): string {
  return obj.name;      // ✅ 现在可以了
}
```

读作："**`T` 可以是任何类型，只要它至少长得像 `{ name: string }`。**"

**类比**：招聘要求"必须会 React"。
你可以是前端、可以是全栈、可以是刚毕业的——**但你必须会 React**。
一旦这个要求立住了，公司就敢让你去写 React 组件了。

### 约束不满足时的报错

```ts
function getLength<T extends { length: number }>(x: T): number {
  return x.length;
}

getLength(123);
```

```text
error TS2345: Argument of type 'number' is not assignable to parameter of type '{ length: number; }'.
```

**人话**：`number` 没有 `length` 属性，不满足约束。

### 显式指定类型参数时的报错（注意错误码不同）

```ts
function onlyString<T extends string>(x: T): T {
  return x;
}

onlyString<number>(1);
```

```text
error TS2344: Type 'number' does not satisfy the constraint 'string'.
```

**注意 `TS2344` 和 `TS2345` 的区别**：

- `TS2345` = 你**传的值**不满足约束（参数位置的错误）
- `TS2344` = 你**显式写的类型参数**不满足约束

### `extends` 在泛型里的含义 ≠ 类继承的含义 ★

这是个高频面试点：

```ts
// 这里的 extends 是"类继承"
class Dog extends Animal {}

// 这里的 extends 是"约束/兼容"，意思是"必须能赋值给"
function f<T extends Animal>(x: T) {}
```

在泛型里，`T extends U` 的准确含义是：
"**T 的每一个可能取值，都必须能赋值给 U。**"

所以它跟"继承"没必然关系：

```ts
// Point2D 没有 extends 任何东西，但它"满足" { x: number }
function logX<T extends { x: number }>(p: T) {
  console.log(p.x);
}
logX({ x: 1, y: 2 });      // ✅ 对象字面量也行
```

### 约束组合：`extends` + `keyof`（超实用的组合）

这是泛型里最有用的一个套路，请一定掌握：

```ts
function get<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}

const user = { id: 1, name: 'Tom', active: true };

const id = get(user, 'id');
//    ^? number
const name = get(user, 'name');
//    ^? string
```

**逐字拆解**：

- `T` = 对象的类型（自动从 `user` 推断出 `{ id: number; name: string; active: boolean }`）
- `K extends keyof T` = "K 必须是 T 的某个键名"（`keyof T` 得到 `'id' | 'name' | 'active'`）
- `T[K]` = "T 中键 K 对应的值的类型"（索引访问类型）

**打错键名立刻报错**：

```ts
get(user, 'nmae');
```

```text
error TS2345: Argument of type '"nmae"' is not assignable to parameter of type '"id" | "name" | "active"'.
```

**而且精确到字面量**：如果你写 `get(user, 'i' as 'id' | 'name')`，返回类型会是 `number | string`。

**这个模式的实际用途**：所有"通过键名从对象里取值"的函数（`lodash.get`、ORM 的字段选择、i18n 的 key 检查）。

### 多个约束：用 `&` 交叉

```ts
function f<T extends { id: string } & { createdAt: Date }>(x: T) {
  return `${x.id} @ ${x.createdAt.toISOString()}`;
}
```

> **一句话记住它：`T extends U` 读作"T 必须能赋值给 U"，它给 T 划了一个范围——有了范围，编译器才敢让你用范围内的能力。**

## 5.5 泛型默认值

```ts
interface ApiResponse<T = unknown> {
  data: T;
  ok: boolean;
}

const a: ApiResponse = { data: { anything: 1 }, ok: true };       // T 用默认值 unknown
const b: ApiResponse<number> = { data: 1, ok: true };             // T 显式指定
```

**默认值让泛型从"必须写"变成"可选写"**，这对降低使用门槛很有帮助。

**默认值可以引用前面的类型参数：**

```ts
interface Pair<A, B = A> {
  first: A;
  second: B;
}

const same: Pair<number> = { first: 1, second: 2 };
const mixed: Pair<number, string> = { first: 1, second: 'a' };
```

**默认值也可以和约束组合：**

```ts
type HttpMethod = 'GET' | 'POST' | 'PUT' | 'DELETE';

interface RequestConfig<M extends HttpMethod = 'GET'> {
  method: M;
}

const r1: RequestConfig = { method: 'GET' };
// const r2: RequestConfig = { method: 'POST' };   // ❌ 默认是 'GET'，只能填 GET
const r2: RequestConfig<'POST'> = { method: 'POST' };   // ✅
```

**React 里最常见的用法：**

```ts
interface Props<T = string> {
  value: T;
  onChange: (next: T) => void;
}
```

> **一句话记住它：泛型默认值 `T = X` 让调用者可以省略类型参数，是"渐进式类型"哲学在泛型上的体现。**

## 5.6 泛型的推断：为什么你大部分时候不用写

### 从参数推断（最爽的一种）

```ts
function identity<T>(x: T): T { return x; }

// 你不用写 <number>
const a = identity(42);
//    ^? 42
```

**TS 从 `x` 的实参"反推"出了 `T`。**

这也是为什么前几章的实例代码里，你几乎没见过 `<number>` 这种写法。

### 从返回值推断？不行

```ts
function makeArray<T>(): T[] {
  return [];
}

const arr = makeArray();      // T 推断成 unknown，因为没有线索
const arr2 = makeArray<number>();   // 必须显式写
```

**返回值不能用来推断类型参数。** 因为它自己就依赖 `T`，鸡生蛋的问题。

### 什么时候必须显式写 `<T>`

| 场景 | 例子 |
|---|---|
| 函数没有参数（无处推断） | `makeArray<number>()` |
| 想让 T 更宽 / 更窄 | `useState<string \| null>(null)` |
| 参数推断不能满足约束 | `parseJson<User>(text)` |
| 想要"断言式"的返回 | `document.querySelector<HTMLDivElement>('#app')` |

**最后一个特别常见：**

```ts
const el = document.querySelector('#app');
//    ^? Element | null
const el2 = document.querySelector<HTMLDivElement>('#app');
//    ^? HTMLDivElement | null
el2.innerHTML = 'hi';     // 现在可以了，不用 as
```

### 上下文推断也能用泛型

```ts
const nums = [1, 2, 3];
const strs = nums.map((n) => String(n));
//    ^? string[]
```

`map` 的签名是 `map<U>(fn: (v: T, i: number, arr: T[]) => U): U[]`。
`T` 从 `nums` 推断成 `number`，`U` 从回调返回值推断成 `string`。

> **一句话记住它：泛型能推断就推断，推断不出来（或者想覆盖）才手写 `<T>`。**

## 5.7 实战泛型模式（这一节最值钱）

### 模式 1：通用结果包装 `Result<T>`

```ts
type Result<T, E = Error> =
  | { ok: true; value: T }
  | { ok: false; error: E };

function ok<T>(value: T): Result<T, never> {
  return { ok: true, value };
}

function err<E>(error: E): Result<never, E> {
  return { ok: false, error };
}

// 使用
function divide(a: number, b: number): Result<number, string> {
  if (b === 0) return err('除数不能为 0');
  return ok(a / b);
}

const r = divide(10, 2);
if (r.ok) {
  console.log(r.value.toFixed(2));    // 只有 value
} else {
  console.log(r.error.toUpperCase()); // 只有 error
}
```

### 模式 2：类型安全的属性取值 `pluck`

```ts
function pluck<T, K extends keyof T>(items: T[], key: K): T[K][] {
  return items.map((item) => item[key]);
}

const users = [
  { id: 1, name: 'Tom', age: 18 },
  { id: 2, name: 'Jerry', age: 20 },
];

const names = pluck(users, 'name');
//    ^? string[]
const ids = pluck(users, 'id');
//    ^? number[]
// pluck(users, 'nope');   // ❌ 编译报错
```

### 模式 3：类型安全的分组 `groupBy`

```ts
function groupBy<T, K extends keyof T>(items: T[], key: K): Map<T[K], T[]> {
  const map = new Map<T[K], T[]>();
  for (const item of items) {
    const k = item[key];
    const bucket = map.get(k);
    if (bucket) {
      bucket.push(item);
    } else {
      map.set(k, [item]);
    }
  }
  return map;
}

const byAge = groupBy(users, 'age');
//    ^? Map<number, {...}[]>
console.log(byAge.get(18));
```

### 模式 4：类型安全的 `useState` 风格元组

```ts
type Setter<T> = (next: T | ((prev: T) => T)) => void;

function createState<T>(initial: T): [() => T, Setter<T>] {
  let value = initial;
  return [
    () => value,
    (next) => {
      value = typeof next === 'function'
        ? (next as (prev: T) => T)(value)
        : next;
    },
  ];
}

const [getCount, setCount] = createState(0);
setCount(1);
setCount((prev) => prev + 1);
console.log(getCount());      // 2
```

**注意那个 `Setter<T>` 的定义**：

```ts
type Setter<T> = (next: T | ((prev: T) => T)) => void;
```

**这个"值或更新函数"的联合，就是 React `useState` 的类型秘密。**

### 模式 5：类型安全的 `fetchJson`

```ts
async function fetchJson<T>(url: string): Promise<T> {
  const res = await fetch(url);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return (await res.json()) as T;
}

interface User {
  id: number;
  name: string;
}

const user = await fetchJson<User>('/api/user/1');
console.log(user.name);
```

**但这里有个必须强调的坑**：

```ts
return (await res.json()) as T;
```

**这个 `as T` 是骗人的。** 运行时数据长什么样，`T` 完全不知道。
所以更安全的版本是：

```ts
async function fetchJson<T>(
  url: string,
  validate: (raw: unknown) => T,    // 把校验函数传进来
): Promise<T> {
  const res = await fetch(url);
  if (!res.ok) throw new Error(`HTTP ${res.status}`);
  return validate(await res.json());
}
```

**记住：泛型是编译期的关系，不是运行时的保证。**（第 00 章哲学一。）

### 模式 6：泛型 + 约束做"插件系统"

```ts
interface Plugin<TOptions> {
  name: string;
  defaultOptions: TOptions;
  setup(options: TOptions): void;
}

function usePlugin<TOptions>(plugin: Plugin<TOptions>, options: TOptions): void {
  plugin.setup({ ...plugin.defaultOptions, ...options });
}

const loggerPlugin: Plugin<{ level: 'info' | 'warn'; prefix: string }> = {
  name: 'logger',
  defaultOptions: { level: 'info', prefix: '[app]' },
  setup(options) {
    console.log(`${options.prefix} level=${options.level}`);
  },
};

usePlugin(loggerPlugin, { level: 'warn', prefix: '[db]' });
// usePlugin(loggerPlugin, { level: 'debug', prefix: '[db]' });  // ❌ 编译报错
```

> **一句话记住它：泛型模式的价值在于"外壳复用、数据定制"，最典型的就是 `Result<T>`、`ApiResponse<T>`、`Repository<T>`。**

## 5.8 泛型的常见误用（面试官爱问）

### 误用 1：只出现一次的 `T`

```ts
// ❌ T 只出现一次，等于白写
function log<T>(value: T): void {
  console.log(value);
}
log<string>('hi');
log<number>(1);

// ✅ 直接写 unknown 更诚实
function log2(value: unknown): void {
  console.log(value);
}
```

**判断标准**：`T` 至少要出现**两次**（或者出现在约束关系里），它才有"建立关系"的价值。

其实更好的写法是 `function log(value: unknown)`，因为调用者不用纠结要不要写 `<T>`。

### 误用 2：把泛型当 `any` 用

```ts
// ❌ 这就是 any，只是换了个字母
function process<T>(data: T): T {
  (data as any).whatever();
  return data;
}
```

**泛型参数如果被 `as any` 处理了，那泛型就是装饰。**

### 误用 3：过度泛型化

```ts
// ❌ 看着唬人，实际没人能正确调用
function merge<A, B, C, D, R>(
  a: A, b: B, c: C, d: D,
  combiner: (a: A, b: B, c: C, d: D) => R,
): R {
  return combiner(a, b, c, d);
}

// ✅ 需要几个写几个，超过 3 个考虑用对象参数
function mergeObj<T extends object, R>(input: T, f: (v: T) => R): R {
  return f(input);
}
```

**经验值**：一个函数超过 **3 个类型参数**，通常说明设计该拆了。

### 误用 4：以为泛型能"收窄"返回值

```ts
function bad<T>(value: string): T {
  return value as T;      // ❌ 骗编译器
}

const n = bad<number>('hello');
//    ^? number  但运行时是 string
n.toFixed(2);   // 💥 运行时崩溃
```

**这是最危险的一种误用**：它让类型系统和运行时彻底脱节。

> **一句话记住它：`T` 至少出现两次才有意义；用 `as any` 处理 `T` 等于白写；超过 3 个类型参数就该重构。**

## 5.9 `any` / `unknown` / 泛型 对照表

| | `any` | `unknown` | 泛型 `<T>` |
|---|---|---|---|
| 能接受任何值 | ✅ | ✅ | ✅ |
| 能做任何操作 | ✅（危险） | ❌（要先收窄） | ❌（要先约束） |
| 保留类型信息 | ❌ 全丢 | 部分保留 | ✅ 完整保留 |
| 建立输入输出关系 | ❌ | ❌ | ✅ **核心价值** |
| 会传染 | ✅ 严重 | ❌ | ❌ |
| 适用场景 | 迁移旧代码的临时逃生舱 | 外部数据入口 | **复用逻辑 + 保持类型** |

**决策流程：**

```
我要不要"接受任何东西"？
  ├─ 不要 → 写具体类型
  └─ 要
      ├─ 输入输出之间有关系吗？（进来的类型要影响出去的类型）
      │    ├─ 有 → 用泛型 <T>
      │    └─ 没有 → 用 unknown（绝不用 any）
      └─ 我在从 JS 迁到 TS，这里实在来不及 → 临时 any + // TODO 注释 + 记进技术债清单
```

## 5.10 本章小结

```
泛型是什么 ────── 类型层面的"函数参数"
       │            核心价值：建立类型之间的关系（不是"万能"）
       │
用在哪 ────────── 函数 / 接口与类型别名 / 类
       │
命名 ──────────── T U V K E R P，或业务名 TData / TState
       │
约束 T extends U ── 给 T 划范围；没范围就什么都不能做
       │            "T 必须能赋值给 U"（≠ 类继承）
       │            黄金组合：K extends keyof T，返回 T[K]
       │
默认值 T = X ───── 让调用者可以省略类型参数
       │
推断 ──────────── 能从参数推断就推断；返回值无法推断 T
       │
实战模式 ──────── Result<T> / ApiResponse<T> / Repository<T>
       │            pluck / groupBy / useState 式元组 / fetchJson<T>
```

**三句话带走：**

1. **泛型是"类型之间的关系"，不是"万能类型"。** 记住 `T` 至少出现两次才有意义。
2. **无约束的 `T` 什么都不能做。** 想访问属性就得 `T extends { ... }`。
3. **`K extends keyof T` + `T[K]` 是泛型里最实用的一个组合**，几乎每个类型安全的工具函数都用它。
