## 4.1 联合类型：类型的"或"

### 人话

联合类型就是"**这个值可能是 A，也可能是 B**"。

```ts
let id: string | number;

id = 'abc';    // ✅
id = 123;      // ✅
id = true;     // ❌
```

那个竖线 `|` 读作 "**或**"。
（顺便：如果你见过 `&`，那是"且"，叫交叉类型，第 03 章讲过。）

### 为什么需要它

因为 JavaScript 里到处都是"可能是这个也可能是那个"：

```js
function formatId(id) {
  // id 可能是后端给的数字，也可能是前端从 URL 里读出来的字符串
  return typeof id === 'number' ? id.toFixed(0) : id.trim();
}
```

用 `any` 写：

```ts
function formatId(id: any) {
  return typeof id === 'number' ? id.toFixed(0) : id.trim();
}
// 问题：哪天有人传了个对象进来，这里会静默出错，编译器一声不吭
```

用联合类型写：

```ts
function formatId(id: string | number) {
  return typeof id === 'number' ? id.toFixed(0) : id.trim();
  //                                              ^? 这里 TS 已经知道是 string 了
}
formatId({});   // ❌ 编译期直接报错
```

**联合类型的价值**：它把"可能是几种"这个事实**写下来**了，于是编译器能守住边界。

### 联合类型的"共同点"规则

**你不收窄，就动不了。**

```ts
type Pet = { meow(): string } | { bark(): string };

function play(p: Pet) {
  return p.meow();
}
```

```text
error TS2339: Property 'meow' does not exist on type 'Pet'.
  Property 'meow' does not exist on type '{ bark(): string; }'.
```

**读这个报错的方法**：第一行说"Pet 上没有 meow"。第二行告诉你**具体是哪个成员出了问题**——
`{ bark(): string }` 这个成员没有 `meow`。

**规则：在联合类型上，你只能访问所有成员都有的属性。**

```ts
type A = { id: number; name: string };
type B = { id: number; age: number };
type AB = A | B;

declare const v: AB;
v.id;      // ✅ 两边都有 id
v.name;    // ❌ A 有 B 没有
```

> **一句话记住它：联合类型是"或"。不收窄，就只能用交集。**

## 4.2 字面量类型：TS 送你的第一份大礼

### 人话

**一个字面量（比如 `'up'`、`42`、`true`）本身也可以当类型用。**

```ts
type Direction = 'up' | 'down' | 'left' | 'right';

let d: Direction = 'up';    // ✅
d = 'north';
```

```text
error TS2322: Type '"north"' is not assignable to type 'Direction'.
```

就这一招，你已经把"魔法字符串"这个 bug 源头堵死了。

对比一下 JS 的世界：

```js
// JS：这段代码能跑，但到运行时才发现问题
const config = { direction: 'north' };
```

```ts
// TS：编译期就被拦下
const config: { direction: Direction } = { direction: 'north' };
// ❌ Type '"north"' is not assignable to type 'Direction'.
```

### 为什么 `const` 能推出字面量类型

第 02 章埋了个伏笔，现在解开：

```ts
let a = 'hello';
//  ^? string
const b = 'hello';
//    ^? "hello"
```

- `let` 后面可能被改成别的字符串，所以类型必须放宽成 `string`。
- `const` 永远不可能变，所以类型锁死成 `"hello"`。

**这个机制是 TS 字面量类型的基础。**

### `as const`：让对象也享受 `const` 待遇

对象属性即使你写了 `const`，里面的值还是被放宽的：

```ts
const config = {
  direction: 'up',
  retries: 3,
};
// config.direction 的类型是 string，不是 "up"
// config.retries   的类型是 number，不是 3
```

想锁死？加 `as const`：

```ts
const config = {
  direction: 'up',
  retries: 3,
} as const;

// config.direction 的类型是 "up"
// config.retries   的类型是 3
// 而且所有属性自动变成 readonly
```

**`as const` 的真实用途**（第 06 章还会细讲）：

```ts
// 场景 1：配置表
const ROUTES = {
  home: '/',
  user: '/user/:id',
} as const;
// typeof ROUTES.home 是 "/"，不是 string

// 场景 2：从数组推出联合类型（超实用）
const COLORS = ['red', 'green', 'blue'] as const;
type Color = typeof COLORS[number];
//   ^? "red" | "green" | "blue"
// 这样你就有了一个"数组和类型永不脱节"的写法：
// 往数组里加一个颜色，类型自动跟着变。
```

**最后那个技巧请一定记住**，它在真实项目里出现频率极高。
（`typeof COLORS[number]` 读作"取 COLORS 所有元素类型的联合"，第 06 章解释 `[number]` 是什么意思。）

> **一句话记住它：字面量类型把"只能是这几个值"写成代码，`as const` 让对象和数组也享受这个待遇。**

## 4.3 收窄：TypeScript 最像人的地方 ★★

### 4.3.1 什么是收窄

先看一段代码，注意跟紧每一步：

```ts
function f(x: string | number) {
  // 此刻：x 可能是 string，也可能是 number
  // 类型集合 = { string, number }

  if (typeof x === 'string') {
    // 此刻：x 一定是 string
    // 类型集合 = { string }        ← 缩小了！
    x.toUpperCase();
  }

  // 出了 if：又回到 { string, number }
  x.toFixed(2);
}
```

上面最后一行会报错：

```text
error TS2339: Property 'toFixed' does not exist on type 'string | number'.
  Property 'toFixed' does not exist on type 'string'.
```

**关键洞察：`x` 的类型不是固定的，它随着代码走到哪一行而变化。**

### 为什么这很了不起

在绝大多数静态类型语言里（Java、C#、C++、Go、Rust），
**一个变量的类型在它被声明的那一刻就定死了，整个作用域内都不变。**

你想处理"可能是字符串也可能是数字"的输入，只能：

- 声明成最宽的类型（比如 `Object`），然后用强制转换（cast）
- 或者写一堆重载
- 或者用 `instanceof` + 强制转换

TypeScript 换了个思路：

> **变量声明时说"它可能是这几种"，
> 然后编译器跟着你的 `if` / `switch` / `typeof` 一路走，
> 每走一步就重新计算"现在还可能是哪几种"。**

这个技术叫**控制流分析（Control Flow Analysis）**。

### 类比：机场安检

想象你走进一个园区大门。保安看到你，心里想：

> "这个人可能是员工，可能是访客，也可能是送货的。"

你去闸机刷了员工卡。保安立刻更新认知：

> "他能刷员工卡 → 他一定是员工。现在排除了访客和送货的。"

你去员工餐厅点了餐，保安想："员工也可能带访客进来吃饭。"

**保安的认知跟着你的行为一步步变窄。这就是收窄。**

而且注意：**保安没有问过你"你是什么身份"**。他只观察你**做了什么**。
TypeScript 也一样——它不看你怎么声明，它看你**怎么判断**。

### 4.3.2 收窄的十种手段

下面这张表是本章的核心。每个都配最小例子。

#### 手段 1：`typeof`（最常用）

```ts
function f(x: string | number | boolean | null | undefined) {
  if (typeof x === 'string') return x.toUpperCase();
  if (typeof x === 'number') return x.toFixed(2);
  if (typeof x === 'boolean') return x ? '是' : '否';
  if (x === null) return 'null';
  if (x === undefined) return 'undefined';
  return assertNever(x);   // 到这里 x 是 never
}
```

`typeof` 能识别的返回值只有这 8 个字符串：
`"string"` `"number"` `"bigint"` `"boolean"` `"symbol"` `"undefined"` `"object"` `"function"`。

**注意 `typeof null === 'object'`！** 所以判 `null` 得另写：

```ts
if (typeof x === 'object' && x !== null) {
  // 这里 x 才是真的对象
}
```

#### 手段 2：真值判断（Truthiness）

```ts
function f(x: string | null | undefined) {
  if (x) {
    // x 是 string（排除了 ''、null、undefined）
    return x.toUpperCase();
  }
  return '';
}
```

**但这里有个经典坑！** `if (x)` 会同时排除**空字符串 `''`**：

```ts
f('');   // 你以为是合法输入，但被当成了"没有值"
```

所以：

> **只在"空字符串和 null 等价"的时候用真值判断。**
> 否则老老实实写 `if (x !== null && x !== undefined)`，或者用 `x != null`（它同时排除 `null` 和 `undefined`，是社区很受欢迎的简写）。

#### 手段 3：相等比较

```ts
function f(x: 'a' | 'b' | 'c', y: string | number) {
  if (x === 'a') {
    // x 是 'a'
  }
  if (y === 1) {
    // y 是 1（number 收窄成了字面量 1）
  }
}
```

TS 甚至能推断出"因为 `x === 'a'`，所以后面 `x !== 'a'`"：

```ts
if (x !== 'a') {
  // x 是 'b' | 'c'
}
```

#### 手段 4：`in` 操作符（判属性存在）

```ts
type Cat = { meow: () => string };
type Dog = { bark: () => string };

function play(pet: Cat | Dog) {
  if ('meow' in pet) {
    return pet.meow();     // pet 是 Cat
  }
  return pet.bark();       // pet 是 Dog
}
```

**`in` 是判断"是不是某个形状"的标准手段。**

#### 手段 5：`instanceof`（判类实例）

```ts
function f(x: Date | Error) {
  if (x instanceof Date) {
    return x.getTime();      // x 是 Date
  }
  return x.message;          // x 是 Error
}
```

**注意：`instanceof` 只能用在 class 上，不能用在 interface 上**（第 00 章的哲学一）。

#### 手段 6：`Array.isArray`

```ts
function f(x: string | string[]) {
  if (Array.isArray(x)) {
    return x.join(',');      // x 是 string[]
  }
  return x.toUpperCase();    // x 是 string
}
```

#### 手段 7：`switch` + 字面量

```ts
type Status = 'idle' | 'loading' | 'done' | 'error';

function label(s: Status): string {
  switch (s) {
    case 'idle':    return '待机';
    case 'loading': return '加载中';
    case 'done':    return '完成';
    case 'error':   return '出错';
    default:        return assertNever(s);   // s 是 never，说明全处理了
  }
}
```

#### 手段 8：自定义类型谓词 `x is T` ★

这是**唯一能让你自己定义收窄规则**的手段。

场景：你从后端拿到一个 `unknown`，想判断它是不是 `User`。

```ts
interface User {
  id: number;
  name: string;
}

// 关键在于返回类型写 `user is User`，而不是 `boolean`
function isUser(value: unknown): value is User {
  return (
    typeof value === 'object' &&
    value !== null &&
    'id' in value &&
    typeof (value as User).id === 'number' &&
    'name' in value &&
    typeof (value as User).name === 'string'
  );
}

function handle(input: unknown) {
  if (isUser(input)) {
    // 这里 input 是 User 了！全部因为那个 `is User`
    console.log(input.name.toUpperCase());
  }
}
```

**`value is User` 这个写法叫"类型谓词"（type predicate）。**
它是对编译器的承诺："如果我返回 true，那这个参数就是 User。"

**注意：这是一个承诺，编译器不会去验证你的实现。**
所以写类型谓词时，你实现的检查逻辑必须真的覆盖了 `User` 的所有要求。写漏了，编译期不会有任何提示，运行时才炸。

#### 手段 9：断言函数 `asserts x is T`

有些场景你想"检查失败就直接抛错"，而不是返回 boolean：

```ts
function assertIsUser(value: unknown): asserts value is User {
  if (
    typeof value !== 'object' ||
    value === null ||
    !('id' in value) ||
    !('name' in value)
  ) {
    throw new Error('不是合法的 User');
  }
}

function handle(input: unknown) {
  assertIsUser(input);
  // 这行之后，input 就是 User 了！
  console.log(input.name);
}
```

**关键点**：`asserts` 函数**必须**被调用在 `function` 声明或 `const` 箭头函数里，
而且在它之后的代码里收窄才生效。（它是少数依赖"副作用注释"的特性。）

`console.assert`、Node 的 `assert` 模块、测试库的 `expect` 都是这个模式的近亲。

#### 手段 10：赋值收窄

```ts
function f() {
  let x: string | number = 'hello';
  //  ^? string | number
  x = 42;
  //  ^? number        ← 赋值把类型收窄了
}
```

这个很自然：你刚把它设成什么，它就是什么。

> **一句话记住它：收窄是"跟着判断走"的。TS 不看你声明了什么，它看你判断了什么。**

### 4.3.3 收窄为什么会突然失效（新手必踩）

收窄在**闭包**里有个坑。看这段：

```ts
function f(x: string | null) {
  if (x !== null) {
    setTimeout(() => {
      console.log(x.toUpperCase());   // ✅ 这个能通过
    });
  }
}
```

能通过。但如果你在闭包里给它重新赋值：

```ts
function f() {
  let x: string | null = Math.random() > 0.5 ? 'hi' : null;

  if (x !== null) {
    const fn = () => {
      x = null;                        // ← 在闭包里改了它
      console.log(x.toUpperCase());
    };
    fn();
  }
}
```

```text
error TS18047: 'x' is possibly 'null'.
```

**规则：只要一个变量在任何嵌套函数里被赋过值，TS 就会放弃在闭包里对它做收窄。**

原因很直白：TS 不知道闭包什么时候被执行、执行几次。
既然它无法保证"你进这个闭包时 `x` 还是非 null"，就不敢给你保证。

**实战建议**：

- 想保住收窄，进闭包之前**把值存到 `const` 里**。
- 这也是函数式风格受欢迎的原因之一。

```ts
// ✅ 好：先存 const，闭包里用的是快照
function f(x: string | null) {
  if (x === null) return;
  const value = x;              // 现在是 const，收窄锁死了
  return () => value.toUpperCase();
}
```

## 4.4 判别联合 ★★★：本章的王牌

> 如果你这一章只学一个东西，学这个。
> 它是 TypeScript 里**性价比最高的设计模式**，没有之一。

### 先看一个"到处都是可选字段"的坏例子

假设你在写一个"加载用户信息"的功能。用一个类型描述所有状态：

```ts
// ❌ 坏设计
interface State {
  loading?: boolean;
  data?: User;
  error?: string;
}
```

这个类型**允许**下面所有荒谬的组合：

```ts
const s1: State = { loading: true, data: user, error: '失败了' };  // 又在加载又有数据又报错？
const s2: State = {};                                              // 什么都没有？
const s3: State = { data: user, error: '出错了' };                  // 有数据还报错？
```

**编译器全都不拦。** 因为每一行都满足 `State` 的定义。

于是你只能靠人脑记住"到底哪些组合是合法的"，然后在业务代码里写满防御：

```ts
function render(s: State) {
  if (s.loading) { /* ... */ }
  else if (s.error) { /* ... */ }
  else if (s.data) { /* ... */ }
  // 那 loading 和 error 同时存在呢？那 data 是 undefined 呢？
  // 你永远写不完这些 if
}
```

**这就是"非法状态可以被表示"（illegal states representable）。**
它是 bug 的最大温床。

### 判别联合：让非法状态写不出来

```ts
// ✅ 好设计
type State =
  | { status: 'idle' }
  | { status: 'loading' }
  | { status: 'success'; data: User }
  | { status: 'error'; error: string };
```

那个 `status` 字段叫**判别属性（discriminant）**。
它必须是一个**字面量类型**，而且每个成员都不一样。

现在上面那些荒谬的组合，**一个字都写不出来了**：

```ts
const s1: State = { status: 'loading', data: user };
```

```text
error TS2353: Object literal may only specify known properties,
  and 'data' does not exist in type '{ status: "loading"; }'.
```

```ts
const s2: State = { status: 'success' };
```

```text
error TS2741: Property 'data' is missing in type '{ status: "success"; }'
  but required in type '{ status: "success"; data: User; }'.
```

```ts
const s3: State = { status: 'success', data: user, error: 'x' };
```

```text
error TS2353: Object literal may only specify known properties,
  and 'error' does not exist in type '{ status: "success"; data: User; }'.
```

**编译器现在成了你的业务规则守门员。**

### 使用起来是什么感觉

```ts
function render(state: State): string {
  switch (state.status) {
    case 'idle':
      return '还没开始';
      // 注意：这里 state 是 { status: 'idle' }，访问 state.data 会报错

    case 'loading':
      return '加载中...';

    case 'success':
      // 这里 state 是 { status: 'success'; data: User }
      // state.data 直接可用，不需要任何可选链！
      return `你好，${state.data.name}`;

    case 'error':
      // 这里 state 是 { status: 'error'; error: string }
      return `出错了：${state.error}`;

    default:
      return assertNever(state);   // 穷尽检查
  }
}
```

**三个巨大好处：**

1. **不需要 `?.` 和 `!`。** 进了 `case 'success'`，`state.data` 就是 `User`，编译器已经证明了。
2. **不可能漏掉分支。** 忘了写 `case 'error'`？`assertNever` 立刻报错。
3. **加新状态时，所有处理点自动报错。** 这是重构时的救命稻草。

### 为什么它这么好用──设计哲学

第 00 章讲过，TS 的目标之一是"**让非法状态无法表示**"（make illegal states unrepresentable）。

判别联合就是这个理念最直接的落地：

> **不要用一个宽类型 + 一堆可选字段 + 一堆 if 来描述"多种情况"。
> 用联合类型，让每种情况成为一个独立的、自洽的形状。**

**判断标准**：如果你在写 `if (a && !b && c)` 这种"组合条件"，八成应该改成判别联合。

### 实战场景 1：API 响应

```ts
type ApiResult<T> =
  | { ok: true; data: T }
  | { ok: false; error: string; statusCode: number };

async function fetchUser(id: string): Promise<ApiResult<User>> {
  try {
    const res = await fetch(`/api/users/${id}`);
    if (!res.ok) {
      return { ok: false, error: '请求失败', statusCode: res.status };
    }
    return { ok: true, data: (await res.json()) as User };
  } catch (e) {
    return { ok: false, error: String(e), statusCode: 0 };
  }
}

// 使用
const result = await fetchUser('1');
if (result.ok) {
  console.log(result.data.name);      // 这里只有 data，没有 error
} else {
  console.log(result.error, result.statusCode);  // 这里只有 error
}
```

这个模式叫 **`Result` 类型**，第 09 章会专门展开。它比抛异常好在**类型系统能追踪到错误**。

### 实战场景 2：UI 状态机

```ts
type FormState =
  | { kind: 'editing'; values: Record<string, string> }
  | { kind: 'validating'; values: Record<string, string> }
  | { kind: 'submitting'; values: Record<string, string> }
  | { kind: 'success'; id: string }
  | { kind: 'failure'; message: string; fieldErrors: Record<string, string> };
```

### 实战场景 3：Redux / Zustand 的 action

```ts
type Action =
  | { type: 'todos/add'; payload: { text: string } }
  | { type: 'todos/toggle'; payload: { id: string } }
  | { type: 'todos/remove'; payload: { id: string } };

// reducer 里每个 case 的 payload 类型都是精确的
function reducer(state: Todo[], action: Action): Todo[] {
  switch (action.type) {
    case 'todos/add':
      return [...state, { id: crypto.randomUUID(), text: action.payload.text, done: false }];
    case 'todos/toggle':
      return state.map((t) => (t.id === action.payload.id ? { ...t, done: !t.done } : t));
    case 'todos/remove':
      return state.filter((t) => t.id !== action.payload.id);
    default:
      return assertNever(action);
  }
}
```

**这就是 Redux Toolkit 类型好用的全部秘密。**

> **一句话记住它：判别联合把"多种情况"从"一个宽类型 + 一堆 if"变成"几个互相排斥的精确形状"，让非法状态根本写不出来。**

## 4.5 `never` + 穷尽检查：配套使用

第 02 章介绍过 `never`，这里把它和判别联合拼在一起，形成完整套路。

```ts
// 这个函数的作用只有一个：当"不该发生"的事情发生时，编译期报错
function assertNever(value: never): never {
  throw new Error(`分支未穷尽，收到了: ${JSON.stringify(value)}`);
}
```

**用法**：在每个处理联合类型的地方，`default` 分支写 `assertNever(x)`。

```ts
type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'square'; side: number };

function area(s: Shape): number {
  switch (s.kind) {
    case 'circle': return Math.PI * s.radius ** 2;
    case 'square': return s.side ** 2;
    default:       return assertNever(s);
  }
}
```

现在给 `Shape` 加一个成员：

```ts
type Shape =
  | { kind: 'circle'; radius: number }
  | { kind: 'square'; side: number }
  | { kind: 'triangle'; base: number; height: number };
```

`area` 立刻报错：

```text
error TS2345: Argument of type '{ kind: "triangle"; base: number; height: number; }'
  is not assignable to parameter of type 'never'.
```

**这个报错就是你要的东西。**

如果没写 `assertNever`，`area` 会默默返回 `undefined`，然后在某个线上环境的深夜爆炸。

**养成习惯：凡是 `switch` 联合类型，`default` 一律写 `assertNever`。**

> **一句话记住它：`assertNever` 把"忘记处理新分支"这个运行时事故，变成编译期红灯。**

## 4.6 可选链 `?.` 和空值合并 `??`

这两个是配合收窄用的日常工具。

### `?.` 可选链

```ts
type User = {
  name: string;
  address?: {
    city: string;
    geo?: { lat: number; lng: number };
  };
};

declare const u: User;

u.address.city;
```

```text
error TS18048: 'u.address' is possibly 'undefined'.
```

用可选链：

```ts
const city = u.address?.city;              // string | undefined
const lat = u.address?.geo?.lat;           // number | undefined
```

**关键特性：整条链短路。**

```ts
u.address?.geo.lat
// 等价于：如果 u.address 是 null/undefined，整个表达式直接是 undefined，不再往下走
// 如果 u.address 存在，那就正常取 .geo.lat —— 注意这里的 .geo 没有 ?.
```

也就是说：**`?.` 之后的整条链，只要前面断了就整个放弃。**

**别到处撒 `?.`。** 如果 `u.address` 按业务逻辑绝不该是 undefined，那你的类型就写错了：

```ts
// 要么类型写对
type User = { name: string; address: { city: string } };

// 要么在使用点显式处理
if (!u.address) throw new Error('用户缺少地址');
const city = u.address.city;      // 之后就不用 ?. 了
```

**判断标准**：`?.` 用多了，通常说明类型定义不准确。

### `??` 空值合并 vs `||` 逻辑或

这是**最容易造成线上 bug 的地方之一**：

```ts
// ❌ 用 ||：0、''、false、NaN 都会被当成"没有值"而替换掉
const port = config.port || 3000;
// 如果 config.port 是 0（合法端口），你会得到 3000！

const count = input.count || 10;
// 如果用户输入 0，你会得到 10！

// ✅ 用 ??：只有 null 和 undefined 才替换
const port = config.port ?? 3000;
// config.port 是 0 → 得到 0 ✅
const count = input.count ?? 10;
// input.count 是 0 → 得到 0 ✅
```

**规则：默认值一律用 `??`，除非你确实想连 `0` / `''` / `false` 一起替换。**

（顺带：`||=` 对应 `??=`。`a ||= b` 和 `a ??= b` 的区别同上。）

### `!` 非空断言：请谨慎使用

```ts
const el = document.getElementById('app');
el.innerHTML = 'hi';
```

```text
error TS18047: 'el' is possibly 'null'.
```

你可以用 `!` 告诉编译器"我保证它不是 null"：

```ts
const el = document.getElementById('app')!;
el.innerHTML = 'hi';    // 编译通过
```

**但 `!` 跟 `as` 一样，是"承诺"，不是"请求"。** 它只是把编译器的嘴堵上，运行时该炸还是炸。

**更好的写法**：

```ts
const el = document.getElementById('app');
if (!el) throw new Error('#app 不存在');
el.innerHTML = 'hi';      // 收窄了，不需要 !
```

> **一句话记住它：默认值用 `??` 不用 `||`；`?.` 和 `!` 用多了说明类型没写对。**

## 4.7 类型谓词的一个现代变化（TS 5.5+）

从 TypeScript 5.5 开始，编译器可以**自动推断**出一些简单的类型谓词。

```ts
type Pet = { kind: 'cat'; meow: () => string } | { kind: 'dog'; bark: () => string };

function isCat(p: unknown) {
  // 注意：没写返回类型
  return typeof p === 'object' && p !== null && 'meow' in p;
}

function use(p: Pet) {
  if (isCat(p)) {
    return p.meow();     // ✅ 通过！编译器自己推断出了 `p is object & { meow: unknown }`
  }
  return p.bark();
}
```

**但只要你写了显式的 `: boolean` 返回类型，推断就被关掉了：**

```ts
function isCat(p: unknown): boolean {     // ← 多了 : boolean
  return typeof p === 'object' && p !== null && 'meow' in p;
}

function use(p: Pet) {
  if (isCat(p)) {
    return p.meow();
  }
}
```

```text
error TS2339: Property 'meow' does not exist on type 'Pet'.
  Property 'meow' does not exist on type '{ kind: "dog"; bark: () => string; }'.
```

**实战建议**：

- 自动推断很方便，但**读代码的人看不出这个函数是个类型守卫**。
- **推荐还是显式写 `value is T`**，因为它是一份文档，明确告诉阅读者"这个函数会收窄类型"。
- 如果写了 `: boolean`，就等于主动放弃了收窄能力——这时候你要问自己"我是故意的吗"。

> **一句话记住它：想让它收窄，就别写 `: boolean`；最好还是显式写 `x is T`。**

## 4.8 本章坑速查

| 坑 | 现象 | 解法 |
|---|---|---|
| 在联合类型上访问非共有属性 | `TS2339: Property 'x' does not exist on type 'A \| B'` | 先收窄（`in` / `typeof` / 判别属性） |
| 字面量联合被赋了别的值 | `TS2322: Type '"north"' is not assignable to type 'Direction'` | 检查值，或放宽类型 |
| 用 `if (x)` 判空字符串 | 空字符串被当成"没有值" | 用 `x != null` 或显式比较 |
| 用 `\|\|` 给数字设默认值 | `0` 被替换掉了 | 用 `??` |
| `typeof null === 'object'` | 判对象时漏了 null | `typeof x === 'object' && x !== null` |
| `instanceof interface` | `TS2693: only refers to a type` | 用 `in` 或换成 class |
| 闭包里收窄失效 | `TS18047: 'x' is possibly 'null'` | 进闭包前存成 `const` |
| `switch` 漏了分支 | 静默返回 `undefined` | `default: assertNever(x)` |
| 类型谓词实现写漏了 | 编译期不报错，运行时炸 | 仔细核对谓词的检查逻辑 |
| 判别属性忘了用字面量 | 收窄不生效 | 用 `status: 'idle'` 而不是 `status: string` |

---

## 4.9 本章小结

```
联合类型 A | B ────── "或是"，不收窄就只能用交集
       │
字面量类型 'a' | 'b' ── 把"只能是这几个值"写进代码
       │                as const 让对象/数组也享受这个待遇
       │
收窄（Narrowing）───── 跟着控制流走，类型集合一步步缩小
       │                typeof / 真值 / 相等 / in / instanceof
       │                Array.isArray / switch / x is T / asserts / 赋值
       │
判别联合 ──────────── 每种情况一个精确形状 + 一个字面量判别属性
       │                ★ 本章王牌，业务代码最高性价比模式
       │
never + assertNever ── 穷尽检查，漏分支立刻编译报错
```

**三句话带走：**

1. **别用"宽类型 + 一堆可选字段"，用判别联合。** 让非法状态根本写不出来。
2. **`switch` 联合类型，`default` 一律写 `assertNever`。** 这是你最该养成的习惯。
3. **默认值用 `??` 不用 `||`。** 这一条能帮你避免线上事故。
